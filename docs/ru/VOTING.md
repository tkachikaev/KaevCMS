# Голосование

Модуль позволяет настроить подключение к рейтингу KTreon. В этой версии доступны настройки и проверка API; голосование из кабинета и автоматическое начисление доступны после явного включения доступа.

1. Владелец включает Voting в **Панель управления → Модули**. При установке применяются миграции модуля.
2. В KTreon откройте **Мои проекты → Проект → Интеграция голосования**, выпустите ключ с правами `vote-intents:create` и `vote-events:read`. Скопируйте ID проекта и ключ (ключ показывается один раз).
3. В KaevCMS откройте **Голосование → Провайдеры → KTreon**. Введите ID проекта и API-ключ, сохраните настройки. Провайдер по умолчанию отключён.
4. Нажмите «Проверить подключение». Проверка читает не более одного события по HTTPS и не создаёт голос или награду. При изменении ключа или ID проекта проверьте подключение повторно.

Ключ хранится зашифрованным с использованием APP_KEY CMS. Не меняйте APP_KEY при обновлении или восстановлении. Пустое поле при сохранении сохраняет ключ текущего проекта; при смене ID старый ключ удаляется. Не публикуйте ключ, не передавайте его игрокам. При перевыпуске ключа в KTreon сохраните новый ключ в CMS.

Режим «Ждать подтверждения» безопаснее и включён по умолчанию. Настройка «Выдать сразу» несёт риск награждения голосов, которые впоследствии отклонят. Политика применяется к вновь обработанным событиям статуса; выданные предметы автоматически не изымаются. Владелец и администратор управляют настройками, аудитор может их просматривать без доступа к ключу.

Если проверка не проходит, убедитесь в правильности ID, действительности ключа, публикации проекта и доступности ktreon.com по HTTPS с сервера CMS. При ограничении запросов повторите проверку позднее. Успешная проверка означает доступ к чтению событий, а не подтверждение работоспособности выдачи наград.

При обновлении до Voting 0.4.0 примените миграции модуля в разделе **Панель управления → Модули**. Доступ игрокам по умолчанию закрыт. После подготовки первого приглашения смена подключённого проекта блокируется; перевыпуск ключа того же проекта разрешён.

В разделе **Голосование → Награды** выберите игровой сервер, укажите ID и количество предметов (до 100 разных предметов). Включение набора доступно для сервера, связанного с LoginServer. Сохраните настройки. Аудитор может просматривать их без редактирования. Вкладка «История» отображает обработанные голоса. Изменения наград применяются при первой обработке голоса, а не к уже сохранённым наборам.

## Включение и планировщик

Настройте награды и проверьте текущее подключение. На тестовой установке проверьте голосование, статусы pending/accepted, начисление в Web Inventory и повторную обработку до открытия доступа. В разделе **Голосование → Провайдеры → KTreon → Доступ игрокам** явно подтвердите тестирование и откройте доступ. При смене ключа или отключении провайдера доступ закрывается. Штатный планировщик CMS запускает `php artisan kaevcms:voting-sync` каждые пять минут; отдельный worker не нужен. Ручной запуск из CLI допускает `--pages=1`. Оставляйте модуль включённым для обработки ранее созданных приглашений, даже если остановили новые. Отключение всего модуля останавливает синхронизацию. Последняя успешная синхронизация и безопасный статус ошибки отображаются в настройках провайдера. При ошибке страницы курсор не меняется. Награда поступает в веб-инвентарь пользователя сайта для выбранного сервера, а не напрямую на игровой аккаунт. За переход по ссылке или голос без приглашения CMS предметы не начисляются. Создавайте согласованные резервные копии всей БД CMS, включая журнал начислений и предметы инвентаря: восстановление старого бэкапа после передачи предметов в игру само по себе не гарантирует защиту от повторной выдачи.
