# Универсальные драйверы KaevCMS — актуальное руководство (0.54.2, кандидат QA)

## Назначение и границы

В разделе **Серверы → Драйверы** можно создать, скопировать, импортировать и экспортировать JSON-профиль LoginServer или GameServer. Профиль описывает названия игровых таблиц/полей и поддерживаемые функции. Он **не содержит** адреса БД, пароли, произвольный SQL или PHP. Поддерживается MySQL/MariaDB. MS SQL/PTS **не поддерживается**.

**Рабочие PHP-драйверы Mobius и RUSaCis сохранены.** Изменение каталога не переключает действующий сервер. Чтобы использовать JSON, выберите драйвер в настройках сервера и примените его через подтверждённую проверку подключения. Применённый профиль хранится как неизменяемый снимок с SHA256 и HMAC-привязкой к реквизитам подключения. После смены реквизитов или редактирования JSON нужна повторная проверка и применение.

## Редактор LoginServer

На первом шаге: название, короткий ID, кодировка/сопоставление, схема игрового пароля, функции. Во втором: таблица аккаунтов, колонки логина, пароля и необязательных данных, фиксированные поля регистрации, поля расширений модулей. В отличие от прежних версий, можно оставить только чтение аккаунта (без включения создания или смены пароля). Для записи необходимы логин и пароль, а физическая БД должна иметь **уникальный индекс по колонке логина** и колонку пароля нужной длины.

Доступные схемы пароля: SHA-1/Base64, BCrypt `$2a$`, SHA-1/MD5/SHA-256/Whirlpool (hex). Они выбираются из фиксированного списка. JSON не разрешает произвольный код. Реальное принятие игровым LoginServer пароля и возможности восстановления повторов проверяются отдельно. Правила регистрации логинов по-прежнему ограничены текущей логикой CMS (не произвольные regex в JSON).

## Редактор GameServer

Три шага: настройки, отображение полей персонажей, связи и статистика. JSON описывает структуру `characters`, связи с кланами, героями и замками, фильтры и рейтинги. **Онлайн** считается по `characters.fields.online`, когда это обычная колонка; для прочих способов хранения статуса счётчик не объявляется автоматически. Применённый снимок имеет приоритет над старым PHP-описанием таблицы.

Ограничения: рейтинги EAV и сортировка по удалённым полям не поддерживаются; привязка владельца персонажа через внутренний Account ID не активирована для личных операций; JSON не включает устаревшую Mobius-операцию rescue. Поставка очереди наград, кошелька и пожертвований не менялась.

## Кодировка БД

Поля **Charset** и **Collation** редактируются в первом шаге обоих конструкторов. **У активного JSON-снимка они берутся из профиля и имеют приоритет над стандартным полем кодировки подключения.** Чтобы поменять кодировку, отредактируйте JSON-профиль и примените его заново к серверу. Старые PHP-драйверы используют свои прежние настройки. Некорректная кодировка не должна молча переключать сервер.

## Что проверяется перед применением

Проверка выполняется без записи в игровую БД: соединение, обязательные таблицы/колонки, сопоставления данных. Для аккаунтных операций записи — индекс уникальности логина и пригодная длина колонки пароля. Для заявленных игровых рейтингов/героев/замков — необходимые базовые поля и связи. Ошибки схемы выводятся в отчёте. Это **проверка структуры**, а не доказательство успешной игровой регистрации, входа клиентом или всех пользовательских сценариев.

## Модули и `driver_extensions`

Модуль объявляет необходимые параметры в своём `module.json`, администратор задаёт таблицы/поля в разделе «Для модулей» конструктора. Группа расширения с колонками должна иметь **ровно одну** таблицу (`kind: table`); несколько разных таблиц описываются отдельными группами. При включении обязательного расширения CMS проверяет заполненность значений и физическое существование объявленных таблиц и колонок. При чтении значений модулем схема проверяется повторно; если она изменилась, выдаётся пустой ответ. Для пользовательского JSON разрешён **только проверенный, применённый снимок**, а не черновик из каталога. Для прежних PHP-драйверов доступен шаблон комплектного профиля.

Сам модуль обязан использовать безопасный Query Builder, контролировать права, владельца записи и ограничения игровой операции. Проверка существования таблицы **не выдаёт права на запись** и не заменяет бизнес-проверки.

## Проверки и готовность

Автономные тесты без Composer/БД: `php tests/Integration/UniversalDrivers/validate-profiles.php`, `validate-write-profiles.php`, `validate-editor-drafts.php`, `validate-schema-preflight.php`. Полноценная приёмка требует MySQL/MariaDB на отдельной тестовой схеме, PHPUnit, PHPStan, Playwright, испытаний обновления Windows/VDS/shared и сверки игрового клиента. **0.54.2 здесь — кандидат для QA, не подтверждённый production-релиз.**
