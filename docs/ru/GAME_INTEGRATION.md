# Интеграция с игровыми серверами

KaevCMS разделяет собственную базу CMS и внешние базы LoginServer/GameServer.

## Драйверы

GameServer-драйвер L2J Mobius использует канонический идентификатор `l2j_mobius`. LoginServer и GameServer намеренно используют одинаковый идентификатор в двух отдельных реестрах. Legacy-вариант LoginServer для C1/C4 сохраняет идентификатор `l2j_mobius_legacy`.

KaevCMS использует один GameServer-драйвер с профилями схем вместо дублирования драйвера для каждой хроники. Inspector выбирает legacy-профиль при наличии `characters.karma` и modern-профиль при использовании `characters.reputation`. Обязательные игровые таблицы: `characters` и `clan_data`. Полные таблицы `heroes` и `castle` включают соответствующие необязательные разделы статистики; отсутствие или неполная структура этих таблиц не отключают рейтинги персонажей.

Проверка подключения и runtime-запросы используют единый контракт обязательных таблиц и колонок, не выводя реквизиты. Публичная статистика включается отдельно для каждого GameServer и имеет независимые лимиты рейтингов уровня, PvP, PK и игрового времени.

## Аккаунты и персонажи

Игрок создаёт связанные игровые аккаунты через настроенный драйвер LoginServer. Страницы персонажей обращаются к GameServer с кешированием и коротким cooldown при сбоях. Аватар профиля CMS не смешивается с аватарами персонажей.

## Очередь наград

Сначала KaevCMS хранит награды в собственном веб-инвентаре. При переносе создаётся идемпотентная нейтральная запись в `kaev_reward_queue` выбранной игровой базы. Владелец сервера сам выбирает обработчик: Java-плагин, скрипт, SQL-задачу, собственный модуль GameServer или другую интеграцию. KaevCMS не изменяет игровые таблицы `items` и не создаёт игровые object ID.

## Каталог предметов и изображения

`GameItemCatalog` — единый API для Promo Codes, Daily Rewards, Web Inventory и журналов наград. Статические каталоги находятся в `resources/game-items`: `interlude`, `classic`, `high-five` и `shine-maker`.

Каждая запись связывает ID с английским названием из каталога и исходным ключом иконки:

```json
{
  "907": {
    "icon": "accessary_necklace_of_anguish_i00",
    "name_en": "Necklace of Anguish"
  }
}
```

Профиль определяется по хронике GameServer. Значения вроде `Classic 3.5 Tales Untold`, `High Five`, `h5`, `shineMaker` и `Shine Maker` нормализуются к нужному каталогу. При передаче числового ID GameServer CMS читает реальную хронику сервера и не откатывается молча к Interlude.

Ручные названия из `lang/{locale}/items.php`, включая переопределения конкретного сервера, имеют приоритет. При отсутствии русского перевода используется английское название из каталога.

Изображения не входят в релизы KaevCMS. Исходные WebP размещаются в общем пуле без копий:

```text
public/game-assets/items/{icon_key}.webp
```

Старый путь `public/game-assets/items/{profile}/{icon_key}.webp` остаётся fallback, поэтому пакет Interlude из 0.33.6 продолжает работать. Числовые серверные и общие переопределения из `public/uploads/game-assets/items` сохраняют приоритет.

Пакеты аватаров находятся в `public/game-assets/characters/{profile}`. Пустая иерархия создана для всех четырёх профилей; серверные и общие переопределения из `public/uploads/game-assets/characters` имеют приоритет.
