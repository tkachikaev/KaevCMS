# Почта, планировщик и очереди

KaevCMS поддерживает синхронную отправку, фоновое подключение и очередь в базе данных. Запрошенный асинхронный режим включается только после успешной проверки.

## Настройка асинхронной очереди на Linux VDS

На Ubuntu VDS используйте systemd-службу `kaevcms-queue` из [инструкции Ubuntu VDS, шаг 14](VDS_UBUNTU.md#14-queue-worker-для-асинхронной-почты). Она обрабатывает очереди `mail-probe,mail,default` в этом порядке и нужна только после включения асинхронной отправки.

После каждого обновления перезапустите worker:

```bash
php artisan queue:restart
sudo systemctl restart kaevcms-queue
```

## Планировщик

Запускайте каждую минуту:

```cron
* * * * * cd /var/www/kaevcms && php artisan schedule:run >> /dev/null 2>&1
```

На VDS используйте cron-файл из [инструкции Ubuntu VDS, шаг 13](VDS_UBUNTU.md#13-настройте-планировщик).

На хостинге без постоянного worker команда `kaevcms:queue-drain` обрабатывает очереди `mail-probe,mail,default` в порядке приоритета. Runtime-диагностика показывает heartbeat планировщика, ожидающие задания, ошибки и состояние доставки, не раскрывая payload.

## Обычный хостинг (Plesk, cPanel, DirectAdmin, ISPmanager)

Откройте **Настройки → Почта → Режим отправки**. Внизу страницы раздел «Cron для очереди в базе данных» уже содержит готовую строку cron: в ней подставлены реальный путь к `artisan` (с учётом отдельного каталога ядра при split-установке) и найденный на сервере PHP версии 8.3 или новее. Не берите путь к PHP и `artisan` из подсказок поддержки хостинга без проверки: сайт требует PHP 8.3+, а `artisan` лежит в каталоге ядра, а не в публичной папке.

1. Скопируйте строку cron (или короткую команду для панелей с отдельным полем расписания, например Plesk) и создайте задание «каждую минуту».
2. Нажмите **Проверить cron**. Проверка ждёт следующего настоящего запуска планировщика и показывает «Работает», только если запуск произошёл после нажатия.
3. Выберите режим «Асинхронный с очередью в базе данных» — тест пройдёт, как только cron обработает тестовое задание.

Если проверка режима не пройдена, под ним показано, почему (например, хостинг запретил `proc_open`, не найден PHP 8.3+, cron не запускался или остановился) и что делать. Синхронная отправка при этом остаётся включённой, письма не теряются и не дублируются. Режим «Асинхронный» не требует cron, но зависит от того, что хостинг разрешает фоновые процессы; если он не подходит, используйте очередь в базе данных.


## Если почтовый сервер недоступен

Письмо из очереди пытается уйти в течение 30 минут: до пяти настоящих ошибок с паузами 1, 3, 5 и 10 минут. Как только почтовый сервер не ответил, вся очередь писем делает паузу на минуту и не тратит попытки, так что зависший сервер не блокирует остальные задания. Ожидание ответа почтового сервера — 10 секунд. Письма, которые не ушли за 30 минут, остаются в неудавшихся заданиях: повторите их на странице очередей в админке, или игрок запросит новую ссылку сам.

Без постоянного worker `kaevcms:queue-drain` отправляет не больше 100 писем в минуту. При массовой регистрации письма придут с задержкой в несколько минут, но не потеряются (замеры: `tests/load/RESULTS.md`).
