# Модули

Модули являются доверенным PHP-кодом, а не изолированными плагинами. Только владелец может устанавливать, включать, подтверждать новую версию, применять миграции, отключать и удалять модуль. Администратор видит состояние модулей, редактор не имеет доступа к их управлению.

Каждый модуль использует строго проверяемый manifest, неизменяемую историю миграций, scoped routes, переводы, views и необязательные пункты навигации. Изменение или удаление уже применённой миграции блокирует runtime-загрузку до решения владельца. Неудачный пакет миграций откатывает только собственные новые изменения.

Встроенный модуль `promo-codes` добавляет одну или несколько привязанных к GameServer наград в основной веб-инвентарь. Отключение или удаление кода сохраняет историю активаций и наград.

Встроенный модуль `daily-rewards` добавляет отдельные месячные календари для игровых серверов. Награда текущего дня выдаётся один раз на подходящий игровой аккаунт через основной веб-инвентарь. См. [Ежедневные награды](DAILY_REWARDS.md).

Встроенный модуль `donations` продаёт монеты кошелька CMS через ЮMoney по цене в рублях, заданной владельцем, и зачисляет их в основной кошелёк только после проверенного подписанного уведомления об оплате. По умолчанию оплата выключена и включается на странице ЮMoney в модуле без изменения `.env`. Дополнительный обмен превращает монеты в игровой предмет в веб-инвентаре отдельно для каждого игрового сервера. См. [Donations](DONATIONS.md).

Модуль может добавить необязательную обложку каталога по пути `assets/module.webp`. KaevCMS обнаруживает её автоматически, если это корректный WebP 320×320 / 512×512 размером не более 2 МБ; иначе в админке остаётся буквенная заглушка.

Promo Codes и Daily Rewards используют общее модальное окно результата для успеха и ошибки, включая иконки и количество выданных предметов.

Установка ZIP через браузер, автоматическое удалённое обновление модулей и sandbox пока намеренно отсутствуют.

Встроенный модуль `support-tickets` добавляет приватные обращения игроков. Владелец и администратор могут отвечать, аудитор работает только на чтение, а доступ редактора включается отдельно в настройках самого модуля. Новые обращения и ответы игроков также создают персональные события центра уведомлений без копирования приватного текста переписки. Документация находится в `modules/support-tickets/docs/README.ru.md`.

## Авторизация административных Livewire-компонентов

Регистрация административного маршрута в `ModuleAdminAccessRegistry` защищает обычный HTTP-маршрут, но не переносит его права автоматически на общий endpoint `/livewire/update`. Административный Livewire-компонент модуля должен использовать `AuthorizesModuleAdminAccess` и проверять зарегистрированное route name перед каждым публичным действием.

Базовый шаблон:

```php
use App\Support\Modules\AuthorizesModuleAdminAccess;

final class ExampleComponent extends Component
{
    use AuthorizesModuleAdminAccess;

    public function save(): void
    {
        $this->authorizeModuleAdminRoute(
            'admin.module-pages.example.update',
            'PUT',
        );

        // Изменение данных выполняется только после проверки.
    }
}
```

`ModuleAdminAuthorizer` является единым источником решения для middleware и Livewire. Не копируйте списки ролей в компонент. Для каждого публичного Livewire action добавляйте регрессии для владельца, администратора, редактора, аудитора и неавторизованного пользователя. Неизвестное route name блокируется по принципу fail-closed.

## Названия модулей на разных языках

В `module.json` можно добавить объект `locales`, например: `"locales": {"ru": {"name": "Промокоды", "description": "Награды по промокодам"}, "en": {"name": "Promo Codes"}}`. Для языка разрешены только `name` (до 120 символов) и `description` (до 1000). Это обычный текст, который экранируется Blade. При отображении выбирается текущий язык, затем резервный язык CMS, затем исходный текст manifest. Переводы доступны и для выключенных модулей без запуска их PHP-кода. Идентификаторы и записи аудита не изменяются.

Переводы событий встроенных модулей находятся в `lang/ru/audit.php` и `lang/en/audit.php`. Для нового события добавляйте подпись на обоих языках, сохраняя стабильный код в базе. Для неизвестных событий сторонних модулей остаётся читаемая подпись из кода.

## Что модуль просит у драйвера игровой или логин-базы

Поле `driver_extensions` в `module.json` позволяет модулю объявить, где в базе администратора лежат нужные ему данные (например, таблица премиум-аккаунтов). Администратор заполняет это в драйвере, а включение модуля блокируется, пока обязательное не указано. Подробности, пример и правила безопасности: [UNIVERSAL_DRIVERS.md](UNIVERSAL_DRIVERS.md#точка-расширения-для-модулей-driver_extensions).
