# Автоматическая подготовка Linux-сервера

`deployment/vds/install.sh` готовит **отдельный сервер** под KaevCMS. Саму CMS устанавливает существующий браузерный `/install/`: скрипт не создаёт `.env`, владельца CMS или таблицы приложения.

| Система | Выбираемый PHP |
| --- | --- |
| Ubuntu 24.04 LTS | 8.3 |
| Ubuntu 26.04 LTS | 8.5 |
| Debian 13 | 8.4 |

Используются штатные пакеты ОС, nginx, PHP-FPM, MariaDB и systemd. Другие системы, включая Debian 12, отклоняются до установки пакетов. Нужен полный релиз или checkout с `composer.lock`; Node.js на сервере не требуется. Скрипт рассчитан на один сайт KaevCMS на сервере.

## Запуск

Распакуйте полный релиз в отдельную папку, например `/root/kaevcms-source`, и выполните:

```bash
cd /root/kaevcms-source
sudo bash deployment/vds/install.sh --plan
sudo bash deployment/vds/install.sh --host example.com
```

Для проверки по IP замените `example.com` на IPv4 сервера. Без `--host` адрес запрашивается в терминале. Каталог сайта по умолчанию — `/var/www/kaevcms`; `--root /var/www/other-name` задаёт другой пустой каталог непосредственно в `/var/www`.

До завершения установки `/install/` доступен только с `127.0.0.1` и IPv4 SSH-клиента. Если браузер выходит в интернет с другого адреса, передайте его при подготовке:

```bash
sudo bash deployment/vds/install.sh --host example.com --installer-ip 198.51.100.20
```

При работе через Cloudflare или другой прокси используйте прямое соединение с сервером либо SSH-туннель; не открывайте незавершённый установщик всем посетителям. Для туннеля:

```bash
ssh -L 8080:127.0.0.1:80 user@SERVER_IP
```

Откройте `http://127.0.0.1:8080/install/`. В веб-инсталлере укажите настоящий адрес сайта, а не адрес туннеля.

## Что делает скрипт

- Устанавливает штатные PHP CLI/FPM с расширениями, nginx, MariaDB и Composer.
- Копирует исходники, исключая `.git`, `.env`, базы SQLite, зависимости и runtime из исходной папки. Устанавливает production-зависимости из `composer.lock` от системного пользователя `kaevcms`.
- Создаёт отдельную пустую базу и пользователя со случайным паролем. MariaDB не требуется открывать в интернет.
- Направляет nginx только на `public/`; PHP выполняется только через `index.php` и защищённый вход веб-инсталлера. Проверяет запрет выдачи `.env` и `vendor/autoload.php`.
- Настраивает отдельный пул PHP-FPM и системные таймеры. Очередь и планировщик ждут `storage/app/installed.lock`.
- После завершения веб-инсталлера и удаления им `public/install` закрывает временную запись в корень и `public/`, назначает `.env` и `installed.lock` права `0640`. Эта проверка выполняется раз в минуту отдельным root-owned скриптом вне дерева сайта.

Исходники принадлежат `kaevcms`, веб-процесс — `www-data`. Постоянная запись разрешена в `storage`, `bootstrap/cache` и `public/uploads`. `0777`, изменение SSH, firewall, полное обновление ОС и перезагрузка не используются. При необходимости отдельно разрешите входящие HTTP/HTTPS в firewall и панели провайдера.

## Завершение через веб-инсталлер

Откройте `http://example.com/install/`. Реквизиты пустой базы посмотрите **в своём SSH-терминале**:

```bash
sudo bash /var/www/kaevcms/deployment/vds/install.sh --credentials
```

Введите эти данные на шаге базы. Имя сайта, адрес, владельца CMS и пароль задайте в браузерном мастере. Не публикуйте вывод с паролем базы. Состояние подготовки хранится только у root: `/var/lib/kaevcms-installer/state.json` (`0600`). Не удаляйте его при повторном запуске.

## HTTPS

Для домена, DNS которого уже указывает на сервер, доступны Certbot и автоматическое продление:

```bash
sudo bash deployment/vds/install.sh --host example.com \
  --https --email admin@example.com --accept-acme-terms
```

Ключ `--accept-acme-terms` означает ваше явное принятие [условий Let's Encrypt](https://letsencrypt.org/repository/). Без ключа мастер запрашивает согласие интерактивно. Порты 80/443 должны быть доступны извне. В веб-инсталлере затем укажите адрес `https://example.com`.

## Повторный запуск и обновление

После успешной подготовки повторный запуск проверяет службы и **не копирует код заново**, не меняет настройки nginx, пароль БД, `.env`, таблицы или владельца CMS. Для смены адреса/HTTPS после подготовки используйте настройки nginx и Certbot; повторный запуск не является редактором конфигурации. Прерванную подготовку можно продолжить тем же скриптом; при несовпадении или повреждении состояния нужна ручная диагностика, данные не удаляются.

Для новой версии CMS используйте штатный updater или полное развёртывание по инструкции обновления. Агент обновлений устанавливается отдельно через `install-update-agent.sh` после завершения CMS.

Проверка служб после установки:

```bash
systemctl status nginx mariadb php8.5-fpm
systemctl list-timers 'kaevcms-*'
journalctl -u kaevcms-queue -u kaevcms-scheduler -u kaevcms-finish-setup -n 50
```

В Ubuntu 24.04 замените `php8.5-fpm` на `php8.3-fpm`, в Debian 13 — на `php8.4-fpm`.
