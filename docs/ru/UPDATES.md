# Обновления

KaevCMS выпускается в трёх форматах:

- полный архив исходников;
- Windows-патч с предыдущей версии;
- кумулятивный Update ZIP для поддерживаемого диапазона версий.

Публичная cumulative-линия начинается с `0.42.4`. Пакет `KaevCMS-cumulative-update-0.42.4-0.44.12-to-0.44.13.zip` обновляет поддерживаемые версии от 0.42.4 до 0.44.12 напрямую до 0.44.13.


Кумулятивный архив проверяется правилами самого старого Web Updater из заявленного диапазона, а не только текущим обновлятором. Версии до `0.42.4` в публичную линию обновления не входят. Шаблоны чистой установки и служебные файлы runtime/uploads исключаются из payload. После обновления недостающая защита uploads создаётся приложением автоматически и без перезаписи существующих пользовательских файлов.

## Контракты релиза

Нумерация и история пакетов берутся из `release.json`; файл `VERSION` проверяется как совместимое зеркало. Windows setup, apply, update, сборщик shared-hosting и сборщик Web Update отклоняют противоречивые метаданные. Runtime-каталоги и защищённые значения окружения задаются через `deployment/windows/update-contract.json`, а история удаления и восстановления читается из `deployment/updates/deletions.json`.

## Источник пакета

Загружайте обновления только из официального репозитория KaevCMS и сверяйте SHA-256 с опубликованным файлом контрольных сумм. CMS проверяет целостность архива и каждого файла внутри пакета, но администратор отвечает за выбор доверенного источника загрузки.

## Перед обновлением

1. Сохраните `.env`, базу CMS, публичные uploads и собственные изображения.
2. Сверьте SHA256 архива с опубликованной контрольной суммой.
3. Загружайте пакеты только из доверенного источника. Текущие пакеты проверяют целостность manifest и файлов, но пока не имеют отдельной криптографической подписи издателя.
4. Не заменяйте runtime-секреты и `storage` файлами из полного архива.

## Shared-hosting

Используйте Web Updater в административной панели. Он проверяет диапазон версий, manifest, SHA256 каждого файла, запрещённые пути, свободное место, резервные копии и состояние восстановления.

Web Updater должен работать только при наличии прав на изменение файлов установки. Не назначайте `0777` всему проекту только ради прохождения preflight.

В split/shared-hosting схеме фактическая публичная папка читается из сгенерированной runtime-конфигурации. Публичные точки входа не зависят от типа раскладки, а `kaevcms-path.php` защищён от замены и удаления пакетом, поэтому технические домены и собственные имена каталогов сохраняются после кумулятивного обновления.

## Ubuntu VDS

На VDS исходный код принадлежит SSH/deployment-пользователю, а PHP-FPM получает запись только в runtime-каталоги. Поэтому обновление применяется через CLI от владельца проекта:

```bash
cd /var/www/kaevcms
php artisan kaevcms:update /tmp/KaevCMS-update.zip
```

Команда показывает проверки и запрашивает подтверждение. Для автоматизации после собственной проверки пакета:

```bash
php artisan kaevcms:update /tmp/KaevCMS-update.zip --yes
```

Не запускайте команду от `www-data` и не выдавайте PHP-FPM запись на весь исходный код.

## Изменение зависимостей

Если релиз меняет `composer.lock`, используйте полный релиз и выполните:

```bash
composer install --no-dev --optimize-autoloader --no-interaction
```

Не используйте `composer update` на production-сервере.

## Windows

После распаковки патча запустите версионный apply-скрипт, затем:

```powershell
.\deployment\windows\quality.ps1
.\deployment\windows\browser-quality.ps1
```

Порядок действий при прерванном обновлении, правила работы с pending-маркером и резервными копиями описаны в [эксплуатационных инструкциях](OPERATIONS.md).
