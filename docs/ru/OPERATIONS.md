# Эксплуатационные инструкции

Здесь описаны восстановимые сбои production-установки. Перед ручными изменениями сохраните `.env`, базу CMS, публичные uploads, собственные игровые изображения и журналы обновления.

## Прерванное обновление Windows

Windows Updater создаёт pending-маркер и перемещает устаревшие файлы в версионную резервную копию до изменения маркера установленной версии. Пока обновление не завершено, эти данные являются частью восстановления и удалять их нельзя.

1. Откройте самый новый `storage/logs/update-*.log` и найдите первый неуспешный этап.
2. Не изменяйте `.env`, `storage/app/kaevcms/pending-update.json` и `storage/app/kaevcms/update-backups/`.
3. Повторно распакуйте тот же полный патч либо более новый поддерживаемый патч поверх проекта с заменой файлов.
4. Запустите apply-скрипт из распакованного релиза:

   ```powershell
   .\deployment\windows\apply-<version>.ps1
   ```

5. После успешного обновления выполните:

   ```powershell
   .\deployment\windows\quality.ps1
   .\deployment\windows\browser-quality.ps1
   ```

Не копируйте старые `VERSION`, apply-скрипт, `vendor` или `storage` в новый релиз. Не удаляйте pending-маркер ради обхода проверки версии. Если продолжить обновление не удаётся, сохраните журнал и папку резервной копии перед полным восстановлением проекта из заведомо исправной копии.

## Недоступна внешняя база LoginServer или GameServer

Игрок видит безопасное сообщение о недоступности. Пароли, DSN, SQL и stack trace не выводятся. Данные CMS продолжают работать там, где функция не требует обращения к внешней базе.

Проверяйте по порядку:

1. Откройте **Администрирование → Системная информация** и настройки нужного LoginServer или GameServer.
2. Запустите встроенную проверку подключения.
3. Проверьте адрес, порт, имя базы, пользователя, правила firewall, маршрутизацию и TLS.
4. Убедитесь, что выбранный драйвер и профиль схемы соответствуют внешней базе.
5. Восстановите подключение и повторите исходную операцию. Не создавайте вручную связи аккаунтов и записи наград только из-за временной недоступности базы.

Не публикуйте `.env`, пароли БД, полный DSN и необработанный Laravel stack trace. Для поддержки достаточно версии, времени операции, безопасного класса/кода ошибки, ID сервера и журнала без секретов.

## Очередь наград недоступна или результат неизвестен

При подтверждённой ошибке записи награда остаётся либо возвращается в веб-инвентарь. Неопределённый результат получает статус `review`; такую награду нельзя выдавать вручную до сверки.

1. Восстановите подключение к GameServer и проверьте `kaev_reward_queue` штатным SQL установки.
2. Откройте **Администрирование → Очередь наград** и выполните сверку проблемной операции.
3. Сопоставьте audit CMS и внешнюю очередь по UUID операции, ID GameServer, пользователю, персонажу и статусу.
4. Не удаляйте запись `review` и не выдавайте предметы вручную, пока результат очереди не установлен.

## Что сохранить для обращения в поддержку

- версию KaevCMS и имя пакета обновления;
- новый `storage/logs/update-*.log` либо нужный фрагмент Laravel-журнала без секретов;
- UUID операции и ID GameServer/LoginServer, если они доступны;
- точную команду или действие администратора, завершившееся ошибкой;
- подтверждение, что `.env`, uploads, pending-маркер и резервные копии обновления не удалялись.
