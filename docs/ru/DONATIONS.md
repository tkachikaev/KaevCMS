# Donations и ЮMoney

Встроенный модуль Donations продаёт монеты кошелька CMS через ЮMoney и может обменивать монеты на игровые предметы. Монеты зачисляются в [кошелёк](WALLET.md) игрока.

## Настройка в административной панели

1. На **публичном сайте с HTTPS** установите KaevCMS и включите Donations.
2. В **Donations → Валюты и цены** задайте цену одной монеты в рублях (RUB).
3. В **Donations → Платёжные системы → ЮMoney** укажите номер кошелька (он виден после сохранения) и секрет HTTP-уведомлений (он хранится зашифрованно и при повторном открытии обозначен звёздочками).
4. Скопируйте адрес уведомлений из админки в настройки HTTP-уведомлений своего кошелька ЮMoney.
5. Включите **«Принимать платежи через ЮMoney»** и сохраните. CMS проверит рабочий режим с выключенным отладчиком, публичный HTTPS-адрес, MySQL/MariaDB, реквизиты ЮMoney и активную цену в рублях. Если всё готово, оплата открывается для всех игроков, а раздел пополнения автоматически появляется в личном кабинете. Иначе страница покажет, что нужно исправить, и оплата останется выключенной.

Редактировать `.env` и запускать команды Artisan для Donations не нужно.

## Режимы приёма платежей

У приёма платежей три состояния. Текущее показано на обзорной странице Donations:

- **Выключен** («Приём платежей выключен») — игроки не могут начать новую оплату. Это состояние по умолчанию для новой установки.
- **Только выбранный игрок** («Контрольный режим оплаты») — настоящая оплата доступна одному выбранному игроку, чтобы провести контрольный платёж перед общим запуском.
- **Все игроки** («Приём платежей включён») — настоящая оплата доступна всем игрокам.

На странице ЮMoney один переключатель: включён — **«Все игроки»**, выключен — **«Выключен»**. Отдельного выбора test/live нет. Режим **«Только выбранный игрок»** на текущей странице выбрать нельзя; он может остаться только с версии 0.50.11, и сохранение страницы ЮMoney заменяет его на включённый или выключенный приём.

Выключение останавливает только новые оплаты. Подписанные подтверждения уже начатых платежей продолжают обрабатываться, заказы, история и сохранённые подтверждения не теряются.

Кнопка **«Тест»** рядом с адресом уведомлений (видна, когда сайт открыт по публичному HTTPS-адресу) проверяет адрес и секрет HTTP-уведомлений без платежа. После нажатия окно до 5 минут ждёт тестовое уведомление: нажмите «Протестировать» в настройках HTTP-уведомлений на сайте ЮMoney. Если подпись сходится, окно сообщает об успехе и сохраняет настройки. Если пришло уведомление с неверной подписью, окно сразу показывает «Секрет не совпадает», но продолжает ждать: адрес уведомлений открыт для всех, и поддельный запрос не должен сорвать проверку. Верное уведомление ЮMoney, пришедшее следом, всё равно засчитывается. Настоящие платежи в это время обрабатываются как обычно, тестовые уведомления монеты не начисляют.

## Почему нельзя проверить живую оплату на 127.0.0.1

Это локальный адрес: сервер ЮMoney не сможет направить на него уведомление. Для **настоящего** перевода с автоматическим зачислением нужен публичный HTTPS-адрес и сайт с рабочей MySQL/MariaDB. На локальном компьютере автоматические тесты проверяют экран, форму, подпись и расчёты, но не реальное поступление внешнего уведомления. Эти требования проверяются при попытке включения оплаты и отображаются понятным сообщением. Не выключайте проверки подписи ради локального перевода.

## Безопасность платежей

Сервер сам рассчитывает сумму заказа, и изменить её потом нельзя. Подписанное HMAC-SHA256 уведомление должно совпадать с заказом и суммой списания у плательщика (`withdraw_amount`); `amount` показывает, сколько получено после комиссии. Только подписанное уведомление подходящего заказа начисляет монеты, ровно один раз, через кошелёк. Секреты защищены ключом шифрования приложения: сохраняйте этот ключ при обновлениях. Перед приёмом платежей за игровую валюту убедитесь, что условия ЮMoney для вашего кошелька это допускают.

## Прямой обмен монет CMS на игровые предметы

В Donations откройте вкладку **«Перевод монет в игру»**. Для каждого игрового сервера укажите ID игрового предмета, число предметов за **1 монету CMS** и включите обмен. Пример: `item_id=90000`, курс `10` — игрок переводит 5 монет CMS и получает 50 экземпляров предмета ID 90000 в **Web Inventory** выбранного сервера. При курсе 1:1 укажите `1`. По умолчанию обмен выключен.

Игрок открывает **«Перевод монет в игру»** в ЛК, выбирает сервер, число монет и подтверждает операцию. Списание монет из кошелька и начисление предмета в веб-инвентарь проходят атомарно в основной БД CMS, с аудитом и защитой от повторной отправки. После этого игрок самостоятельно передаёт предмет персонажу через уже существующий механизм Web Inventory → `kaev_reward_queue`. Игровые таблицы предметов CMS напрямую не изменяет и доставку в игре не гарантирует.

Обмен **не зависит от ЮMoney**, настройки курса индивидуальны для серверов; администратор не редактирует `.env`. При отключении обмена уже выданные предметы и история операций остаются. Если ошибка возникает до завершения обмена, списание монет откатывается.

Если у игрового сервера есть только настройки курса, его удаление также удаляет этот курс. История обменов, награды и выдачи блокируют удаление сервера и сохраняются, в том числе при отключённом Donations. Другие связи, защищённые базой данных, показываются как понятное предупреждение в окне удаления. Новая миграция меняет только связь настроек курса с сервером; существующие пользователи, кошельки, операции и реквизиты платёжных систем сохраняются.

## Архитектура провайдеров (0.54.5 / Donations 1.16.3)

Подключение второго провайдера подготовлено на уровне сервисов, но **FreeKassa пока не встроена**. Доступным для реальной оплаты остаётся ЮMoney, все его существующие настройки и адрес HTTP-уведомлений прежние.

Только проверенный PHP-драйвер с контрактом `RoutablePaymentProvider` может подготовить заказ, сформировать checkout и маршрутизировать уведомление. Маршрутизирующие поля уведомления не считаются доказательством оплаты: перед записью квитанции обязательна криптографическая проверка драйвера. Универсальный обработчик использует код установленного провайдера, а не значение из HTTP-запроса.

Для уже подписанных и сохранённых квитанций ЮMoney сохраняется чтение формата `kaevcms-signed-yoomoney-v1`. Для других проверенных драйверов введён отдельный формат `kaevcms-signed-provider-v2` с привязкой к провайдеру, защита сохранённых данных осуществляется через Laravel Crypt. Кошелёк, транзакционное зачисление и уникальные ограничения не изменялись.

**Итерация 1 — подготовка архитектуры; запуск новых платёжных систем и новый интерфейс админки относятся к последующим этапам.**

## FreeKassa — техническая подготовка (KaevCMS 0.55.0 / Donations 1.17.0)

В реестр встроен драйвер `freekassa` для официального интерфейса SCI. Используется отдельный защищённый маршрут `POST /payments/freekassa/notify`, проверка подписи MD5 по исходному тексту суммы `MERCHANT_ID:AMOUNT:секрет2:MERCHANT_ORDER_ID`, строгое преобразование денежных сумм без float и учёт уникального номера операции `intid`.

**ВНИМАНИЕ: рабочий приём денег через FreeKassa на этом этапе запрещён в коде.** Формы оплаты и административные тестовые заказы пока не открыты. Режим провайдера `live` отклоняется, успешный `test` callback не начисляет монеты. Это НЕ готовая интеграция для приёма настоящих платежей.

В callback FreeKassa `CUR_ID` — ID способа оплаты, а валюта покупки и статус не заверены подписью. Поэтому реальный приём будет разрешён только после реализации серверной сверки через API и настройки безопасности уведомлений (IP и доверенные прокси). Контролировать реальный тестовый режим FreeKassa нужно также в кабинете мерчанта.

Пока не добавлены: полноценная страница настройки FreeKassa в админке, редактирование доверенных IP, тестовая покупка для администратора, API-сверка. Кнопку возврата IP «по умолчанию» добавлять не будем.

Документация SCI: https://docs.freekassa.net/.

## FreeKassa: IP-адреса и безопасность (KaevCMS 0.55.1 / Donations 1.17.1)

В админке **Пожертвования → Платёжные системы → FreeKassa** есть настройки идентификатора магазина, секретов, валют и доверенных IP-адресов для уведомлений. Адрес callback доступен для копирования: `POST /payments/freekassa/notify` на публичном HTTPS-сайте. В кабинете FreeKassa укажите этот адрес, метод POST и включите тестовый режим отдельно в настройках мерчанта. Рекомендуется проверить, что магазин прошёл модерацию.

- Изначально редактор показывает адреса из официального раздела SCI (на 27.10.2026): `168.119.157.136`, `168.119.60.227`, `178.154.197.79`, `51.250.54.238`. Это **не автоматическая синхронизация** — сверяйте актуальность в https://docs.freekassa.net/.
- Администратор может изменить, добавить или удалить IP (один в строке). После сохранения CMS использует **только сохранённый список**; удалённые адреса не появляются снова. Кнопки «Вернуть по умолчанию» и отключения проверки IP нет.
- Для сайта за Cloudflare или nginx (при необходимости) раскройте **Доверенные прокси** и укажите адреса непосредственных прокси: IP или CIDR. Не добавляйте сюда адреса обычных игроков. Сервер должен корректно добавлять истинный адрес клиента в конец `X-Forwarded-For`. Без явного доверия к TCP-узлу CMS не принимает значения из заголовков как IP FreeKassa.
- Пустой список FreeKassa не отключает безопасность: такие уведомления блокируются. С отключённым провайдером список можно очистить и сохранить; перед включением потребуется снова указать адреса.
- Локальная диагностика **не является подтверждением** получения webhook или успешного платежа. Неверная подпись всегда отклоняется независимо от IP.

**FreeKassa по-прежнему TEST-ONLY:** административная внешняя тестовая покупка и реальное начисление появятся на следующих этапах. Серверный API-опрос статуса/валюты перед реальным начислением обязателен. ЮMoney работает отдельно и не зависит от IP-списка FreeKassa.

## FreeKassa — тестовая покупка администратора (0.55.2 / Donations 1.17.2)

После настройки реквизитов, списка IP и включения FreeKassa в режиме **Тестирование** в разделе **Пожертвования → Платёжные системы → FreeKassa** появится форма «Тестовая покупка» (доступна только Owner/Administrator). Администратор выбирает разрешённую валюту и сумму от 1 до 100 в двух знаках после точки; открывается **внешняя страница FreeKassa**, затем в админке можно обновить список тестов и увидеть подтверждение подписанного уведомления.

**Обязательно сначала включите тестовый режим также в кабинете FreeKassa.** KaevCMS не имеет API для удалённого включения sandbox и не может гарантировать отсутствие реального списания, если мерчант оставил боевой режим. Минимальную сумму и доступный тестовый способ оплаты определяет сам провайдер. При необходимости проверьте доступность по https://docs.freekassa.net/.

- Все тесты сохраняются **отдельно от заказов игроков**, без привязки к CMS-пользователю. Монеты никому не начисляются никогда, включая повторные callback и переключение режимов.
- CMS проверяет серверный IP (список FreeKassa), подпись Secret 2, сумму, магазин, UUID заказа и внешний `intid`. Повторы того же события безопасны; при повреждении БД callback не подтверждается `YES`.
- Настоящий callback принимает строго ограниченные формы `application/x-www-form-urlencoded` и `multipart/form-data` с проверкой дублей. FreeKassa должна отправлять POST на показанный в админке публичный HTTPS URL.
- Тестовый статус «Подписанный callback получен» подтверждает **получение и проверку уведомления**, но не подтверждает, что средства точно не списались или что серверный API будет доступен для реальных платежей.
- Смена секретов во время незавершённого теста сделает старое уведомление непроверяемым: завершите тест перед ротацией или начните новый.
- **Реальная оплата FreeKassa для игроков пока заблокирована** до отдельной API-сверки и релизной приёмки. ЮMoney работает как раньше.


## FreeKassa — реальные платежи (KaevCMS 0.55.3 / Donations 1.17.3)

Это **QA-кандидат до итоговой проверки**, не подтверждённая боевая интеграция. В админке **Пожертвования → Платёжные системы → FreeKassa** укажите **ID магазина**, **секрет 1** для подписи формы, **секрет 2** для проверки callback и **API-ключ FreeKassa**, полученный у провайдера. Выберите необходимые валюты, задайте цены монет и список доверенных IP/прокси; в кабинете мерчанта назначьте показанный публичный HTTPS URL оповещений, метод **POST**. Перед реальными покупками отключите *внешний* тестовый режим FreeKassa, если он включён.

В CMS выберите **Рабочий** режим FreeKassa и включите провайдер. В этой же странице есть отдельный **общий выключатель Donations**: выберите «Включено — разрешены готовые провайдеры». Он относится и к ЮMoney. При выключении блокируются только новые оплаты, подписанные уведомления продолжают приниматься. В личном кабинете игрока FreeKassa появляется рядом с ЮMoney только для подходящих валют. Оплата открывается через подписанную форму HTTPS, а монеты начисляются **не по возврату игрока**, а после уведомления и независимого запроса CMS к `https://api.fk.life/v1/orders`.

- Каждое живое уведомление проверяется по trusted IP, подписи, номеру и исходной сумме. Серверный API должен подтвердить `status=1`, UUID заказа (`merchant_order_id`), ID операции (`fk_order_id`), валюту и полную сумму. `CUR_ID` не является валютой заказа. Числа учитываются в копейках/центах, без float; API с ошибкой или несовпадением **никогда не начисляет** монеты.
- Секреты и монотонный API `nonce` хранятся в зашифрованных настройках CMS; ручные правки `.env` не требуются. ЮMoney работает независимо. Отключение новых оплат не препятствует проверке ранее подготовленного заказа при сохранённом ключе.
- Административный test продолжает работать **только при режиме `test`** и ни при каких условиях не начисляет монеты. Функции «Восстановить IP по умолчанию» нет.
- Важное ограничение: в документации FreeKassa названия `intid` (из SCI) и `fk_order_id` (API) различаются. До реального контрольного платежа не подтверждено, совпадают ли они для вашего мерчанта. В 0.55.4 сравнение этих полей устранено: используем точную проверку заказа, валюты и суммы через API.
- При недоступности API CMS отдаёт 503 вместо `YES`. Убедитесь, что у FreeKassa включена повторная доставка уведомлений; отдельное восстановление потерянных callback и полный QA — **итерация 6**. Не использовать на production без финальной проверки.

Официальная документация: https://docs.freekassa.net/.


## FreeKassa — восстановление и смена секретов (0.55.4 / Donations 1.17.4)

**Статус: QA-кандидат, не готов для приёма реальных средств без финальной проверки.**

Если оплаченный заказ не получил уведомление FreeKassa, откройте **Админка → Пожертвования → Заказы → нужный заказ** и нажмите **«Проверить оплату через FreeKassa»**. Кнопка доступна только владельцу или администратору и только для уже созданных LIVE-подготовок FreeKassa, которые ещё не зачислены. CMS напрямую запрашивает у мерчантского API FreeKassa запись по точному UUID заказа, проверяет единственный статус `1` (оплачен), валюту и полную фиксированную сумму. При успехе запись проходит тот же защищённый сервис зачисления Wallet и сохраняется в журнал. Если API недоступен, данные неполные/чужие или сумма отличается, **начисления нет**. Можно повторить запрос после устранения проблемы; повторное успешное подтверждение никогда не должно начислять второй раз. При приостановке новых оплат поиск по старым заказам доступен с рабочим API-ключом.

Документация FreeKassa не гарантирует совпадение поля `intid` в SCI-уведомлении с `fk_order_id` из API. Начиная с версии 0.55.4, защищённая финансовая идентичность — `fk_order_id`, полученный через API, привязанный к точному `merchant_order_id`, сумме, валюте и статусу. Поле `intid` из callback самостоятельно не подтверждает оплату.

После смены **секретного слова 2** сохраняются до четырёх предыдущих ключей в зашифрованном хранилище, максимум на 24 часа. Они подходят только для уведомлений по заказам, подготовленным до смены ключа. Если платёж задержался сильнее, используйте восстановление через API. При смене самого магазина или API-ключа автоматическое восстановление старых заказов может стать недоступным: требуется проверка в кабинете провайдера.

Проверка восстановления и смены ключей не заменяет тестовый и контрольный реальный платёж у конкретного мерчанта. Перед включением живых оплат проверьте URL оповещений, корректность доверенных IP и прокси, повторные уведомления (`YES`), совпадение валюты и ID с API, идемпотентность Wallet, а также пройдите полные тесты Laravel/MySQL/Playwright. Кнопки восстановления IP по умолчанию нет. Официальная документация: https://docs.freekassa.net/.
