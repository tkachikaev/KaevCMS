# ЮMoney в KaevCMS 0.50.11 / Donations 1.13.0

## Настройка — только через админку

1. Откройте **Donations → Валюты и цены**, включите стоимость 1 монеты в RUB и отображение раздела в личном кабинете.
2. В **Donations → Платёжные системы → ЮMoney** укажите свой кошелёк, секрет уведомлений, включите провайдер, режим **Боевой** и RUB.
3. В личном кабинете ЮMoney настройте отправку HTTP-уведомлений на HTTPS-адрес, указанный в админке (`/payments/yoomoney/notify`). Это настройка внешнего сервиса — CMS не может сделать её за вас.
4. В этом же разделе выберите **«Контрольный платёж»**, найдите активную CMS-учётную запись игрока и сохраните. Только этот игрок сможет открыть платёжную форму. **Никаких DONATIONS_* параметров в .env, Artisan-команд или изменений PHP не нужно.**
5. Проведите один небольшой реальный перевод со своего аккаунта и проверьте зачисление средств в ЮMoney, статус `credited` в CMS, запись Wallet и отсутствие дублей при повторном callback. Это внешний перевод, поэтому реальные деньги могут списаться.
6. Если тесты и перевод прошли успешно, переключите режим на **«Рабочий — все игроки»**.

### Режим «Выключено» и безопасность

Новая установка всегда имеет режим **«Выключено»**; обновление не включает платежи самостоятельно. Остановка приёма новых денег доступна из админки одной кнопкой. Система продолжает принимать **подлинные подписанные уведомления** по ранее подготовленным платежам и начислять по ним монеты — отключать webhook отдельно не нужно. Если приложение/БД недоступны, ЮMoney может повторить уведомление; несохранённый webhook может потребовать ручной проверки.

Включение контрольной и публичной оплаты требует: Production без APP_DEBUG, публичный HTTPS URL сайта, MySQL/MariaDB, активный модуль, отображение пополнений, активный RUB-тариф, включённый YooMoney в live с корректными реквизитами. Админка выдаст понятный список блокирующих причин. Проверка локальная, без обращения к API и без подтверждения совместимости конкретного кошелька.

Сумму и UUID заказа рассчитывает сервер. Подтверждение по HMAC-SHA256 и строгая сверка `withdraw_amount` (списано плательщиком) и `amount` (получено) защищают от подмены. Состояния и аудиты неизменяемы; повтор не начисляет второй раз. Тестовые уведомления не начисляют монеты. Секреты зашифрованы с использованием APP_KEY — его обязательно сохраняйте при обновлениях.

Условия личного кошелька ЮMoney для приёма платежей за игровые монеты администратор должен проверить самостоятельно; ЮMoney и ЮKassa — разные продукты. До контрольного перевода фактическая работа конкретного мерчанта не доказана.
