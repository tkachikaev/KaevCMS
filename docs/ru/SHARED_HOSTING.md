# Установка на обычный хостинг

Разные хостинги по-разному называют публичный каталог домена. KaevCMS не пытается его угадать: передайте точное имя каталога ключом сборки.

## Сборка production-пакета

Стандартный каталог `public_html`:

```powershell
.\deployment\windows\build-shared-hosting-package.ps1
```

Другое имя публичного каталога:

```powershell
.\deployment\windows\build-shared-hosting-package.ps1 `
    -PublicDirectoryName example.hosting.test
```

Собственное имя закрытого ядра и каталог результата:

```powershell
.\deployment\windows\build-shared-hosting-package.ps1 `
    -PublicDirectoryName public_html `
    -CoreDirectoryName private-kaevcms `
    -OutputDirectory D:\Releases
```

Скрипт удаляет скопированный `vendor` и заново создаёт чистый production-only набор зависимостей командой `composer install --no-dev --optimize-autoloader`. После этого он формирует переносимый ZIP с разделителями `/`. Ключ `-IncludeDevelopmentDependencies` предназначен только для временной диагностики и не должен использоваться на публичном сайте.

Рабочие данные из `public/uploads`, `public/storage` и файл `public/hot` в пакет не попадают. В архив создаётся чистый каталог `uploads` с защитным `.htaccess`, запрещающим выполнение PHP-подобных файлов. Поэтому production-пакет можно собирать даже из уже установленной тестовой копии без переноса пользовательских изображений.

## Примеры хостингов

### Beget и распространённые панели cPanel

В каталоге сайта обычно находится `public_html`. Используйте команду без параметров и распакуйте ZIP в родительский каталог сайта:

```text
site-root/
├── kaevcms-core/
└── public_html/
```

Не распаковывайте весь пакет внутри `public_html`.

### Jino

Технический домен может одновременно быть именем публичного каталога. Соберите пакет с точным именем:

```powershell
.\deployment\windows\build-shared-hosting-package.ps1 `
    -PublicDirectoryName a860dbbcc70b.hosting.myjino.ru
```

Распакуйте пакет туда, где панель Jino ожидает каталог домена, чтобы он и закрытое ядро находились рядом.

### Неизвестный хостинг

В настройках домена найдите `Document Root`, «Корень сайта», «Публичная папка» или «Рабочая директория». В `-PublicDirectoryName` передавайте только имя конечного каталога. После распаковки файл `index.php` должен лежать непосредственно в этой публичной папке.

## Правильная структура

```text
parent-directory/
├── kaevcms-core/
│   ├── app/
│   ├── bootstrap/
│   ├── storage/
│   └── vendor/
└── public_html-или-каталог-домена/
    ├── index.php
    ├── .htaccess
    ├── kaevcms-path.php
    ├── install/
    └── uploads/
```

Домен никогда не должен быть направлен на `kaevcms-core`.


## HTTPS во время установки

Web Installer разрешает установку как по HTTPS, так и по HTTP. При незашифрованном соединении он показывает одно заметное предупреждение, но не блокирует проверку MySQL, создание владельца или завершение установки. После успешной установки удалите папку `/install` из публичного каталога домена.

Для тестового стенда, локального IP или закрытой сети можно продолжить по `http://.../install/`. Перед открытием публичного сайта пользователям рекомендуется подключить SSL-сертификат и перейти на `https://`.

Заголовок `X-Forwarded-Proto` учитывается только от локального или частного reverse proxy.

## Изменение домена или протокола после установки

Откройте `.env` в закрытом каталоге ядра и измените `APP_URL`, `APP_FORCE_HTTPS` и `SESSION_SECURE_COOKIE`.

Для HTTP:

```env
APP_URL=http://example.hosting.test
APP_FORCE_HTTPS=false
SESSION_SECURE_COOKIE=false
```

Для HTTPS:

```env
APP_URL=https://example.com
APP_FORCE_HTTPS=true
SESSION_SECURE_COOKIE=true
```

После изменения очистите кеш Laravel через терминал хостинга:

```bash
php artisan optimize:clear
```

Если терминал недоступен, используйте предусмотренную панелью хостинга командную строку или обратитесь в поддержку. После смены домена или протокола удалите старые cookies браузера. Ошибка `419 Page Expired` при входе по HTTP обычно означает, что `SESSION_SECURE_COOKIE` осталось включённым.

## Обновление

На shared-hosting используйте кумулятивный Web Update из панели администратора. Один актуальный пакет обновляет любую указанную в его манифесте поддерживаемую версию — промежуточные архивы устанавливать не требуется.

Диапазон поддерживаемых версий считается подтверждённым только тогда, когда пакет принимает самый старый Web Updater из этого диапазона. Перед выпуском требуется прямой тест загрузки пакета на самой старой сохранённой shared-hosting версии.


### Почему произвольное имя публичной папки не мешает обновлению

Сборщик сохраняет связь split-схемы в двух направлениях:

- `<публичная папка>/kaevcms-path.php` указывает публичным точкам входа расположение закрытого ядра;
- `<ядро>/bootstrap/kaevcms-public-path.php` сообщает Laravel и CLI-командам обновления фактическую публичную папку.

Поэтому каталог может называться `public_html`, `htdocs`, техническим доменом вроде `a860dbbcc70b.hosting.myjino.ru` или любым другим допустимым именем хостинга. Web Update применяет цели `public/...` через активный `public_path()` Laravel и не угадывает имя каталога и не хранит его в коде обновления.

Стандартные и shared-hosting варианты `index.php`, `install/index.php` и `.htaccess` намеренно сделаны одинаковыми. Они сами определяют наличие `kaevcms-path.php`, поэтому кумулятивное обновление не может подменить split-точки входа несовместимым стандартным вариантом. Сам файл `kaevcms-path.php` запрещено заменять или удалять через Update ZIP.
