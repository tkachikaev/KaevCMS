# Модуль «Техническая поддержка»

## Назначение

Модуль добавляет приватные обращения игроков и отдельный интерфейс обработки тикетов в административной панели. Все данные находятся в основной базе KaevCMS. LoginServer и GameServer не используются.

## Возможности игрока

- раздел «Мои обращения» открывается первым;
- форма нового обращения появляется только после нажатия кнопки «Создать обращение»;
- создание обращения с утверждённой категорией;
- приватная переписка без полной перезагрузки страницы;
- статусы «Новое», «В работе», «Ожидает вашего ответа», «Закрыто»;
- самостоятельное закрытие обращения;
- закрытый тикет остаётся доступным для чтения, но игрок не может открыть его повторно.

Категории: игровой процесс, игровой аккаунт, техническая проблема, ошибка сайта, пожертвование и бонусы, жалоба, другое.

## Возможности сотрудников

Владелец и администратор могут просматривать и обрабатывать все обращения. Аудитор работает только в режиме чтения.

Права редактора включаются владельцем раздельно:

- просмотр обращений;
- ответы, назначение и изменение статуса;
- внутренние заметки.

Редактор не получает глобального права управления модулями и не может изменять настройки поддержки. Права ответов и заметок автоматически отключаются без права просмотра.

Сотрудник может изменить только собственный ответ или собственную внутреннюю заметку. Предыдущая версия, автор и время правки сохраняются. Ответы, назначение, закрытие, повторное открытие, правки и внутренние заметки выполняются через Livewire без полной перезагрузки страницы. Форма внутренней заметки свёрнута по умолчанию и оформлена компактным раскрываемым блоком.

## Статусы в интерфейсах

Игрок видит статусы «Новое», «В работе», «Ожидает вашего ответа» и «Закрыто». В административной панели состояние `in_progress` отображается как «Ожидает вашего ответа». Рядом с пунктом «Техническая поддержка» показывается красный счётчик новых обращений и тикетов, ожидающих реакции сотрудников; при нуле он скрыт, а значения выше 99 отображаются как `99+`. После ответа сотрудника игрок видит «Ожидает вашего ответа», а администратор — «Ожидает ответа игрока».

## Ограничения

Владелец настраивает ограничения в настройках модуля. Безопасные значения по умолчанию:

- тема: 3–120 символов;
- первое сообщение: 3–3000 символов;
- ответ или заметка: до 2000 символов;
- не более 5 одновременно открытых обращений;
- не более 10 новых обращений за сутки;
- не более 100 сообщений игрока за сутки;
- не более 300 сообщений в одном тикете;
- не более 20 сохранённых исправлений одного сообщения.

Допустимые диапазоны:

- новые обращения за сутки: 1–50;
- сообщения игрока за сутки: 10–1000;
- сообщения в одном тикете: 20–2000;
- история исправлений сообщения: 1–100;
- одновременно открытые обращения: 1–50;
- максимальная длина темы: 30–120;
- максимальная длина первого сообщения: 300–10 000;
- максимальная длина ответа или заметки: 100–10 000.

Одинаковое сообщение нельзя повторно отправить в течение минуты; дополнительно действуют ограничения частоты запросов. Все значения проверяются сервером, а интерфейс использует те же лимиты для атрибутов полей и счётчиков символов. Изменять ограничения может только владелец.

## Интерфейс администратора

Список обращений использует компактную строку фильтров по образцу раздела «Пользователи». На странице обращения переписка расположена слева, а данные игрока, категория, ответственный и даты — в отдельной правой колонке.

Настройки владельца разделены на вкладки:

- «Основные настройки» — права редакторов, защитные лимиты и срок хранения;
- «Очистка базы» — предварительная оценка и ручной запуск удаления.

Кнопка сохранения относится только к основной форме и расположена после всех её разделов.

## Пагинация

Переписка находится в отдельном прокручиваемом окне. Сразу показываются последние 50 сообщений, а более ранняя история подгружается кнопкой «Показать предыдущие». Внутренние заметки никогда не попадают на страницу игрока.

## Хранение и очистка базы

По умолчанию закрытые обращения хранятся 24 месяца. Владелец может выбрать 6, 12, 24, 36 месяцев или бессрочное хранение.

Очистка:

- никогда не затрагивает активные тикеты;
- не удаляет обращения с отметкой «Не удалять автоматически»;
- выполняется пакетами по 100 тикетов;
- удаляет сообщения, внутренние заметки и историю правок вместе с тикетом;
- при ошибке чтения настроек останавливается без удаления данных;
- может запускаться автоматически раз в сутки;
- поддерживает предварительную проверку без удаления.

Команды:

```bash
php artisan kaevcms:support-tickets-cleanup --dry-run
php artisan kaevcms:support-tickets-cleanup
php artisan kaevcms:support-tickets-cleanup --batch=100
```

Для SQLite доступен ручной вариант после резервного копирования и на периоде обслуживания:

```bash
php artisan kaevcms:support-tickets-cleanup --vacuum
```

Обычный `DELETE` освобождает страницы SQLite для повторного использования, но не всегда уменьшает размер файла. `VACUUM` физически пересобирает файл базы и может временно блокировать запись. Автоматическая очистка `VACUUM` не запускает.

## Установка и обновление

Версия модуля 1.7.2 требует KaevCMS 0.45.1 или новее. После обновления CMS необходимо подтвердить обновление модуля в административном разделе «Модули». Новых миграций нет. Владелец может удалить конкретное закрытое обращение вместе с сообщениями, внутренними заметками и историей правок. Открытые и защищённые от очистки обращения удалить нельзя; администратор, редактор и аудитор не получают право удаления. Существующая пакетная retention-очистка сохранена. Поле поиска в административном списке использует общий компонент полей KaevCMS и поддерживает поиск по номеру обращения. Уведомления по-прежнему не содержат тему, сообщения, имя или почту игрока.

Модуль входит в KaevCMS. При включении применяются миграции модуля с контролем SHA256. Уже применённые миграции нельзя изменять или удалять. Отключение модуля скрывает маршруты и навигацию, но не удаляет данные.

## Изображение модуля

Комплектное изображение модуля размещено по общему пути:

```text
modules/support-tickets/assets/module.webp
```

Формат WebP, 512×512, не более 2 МБ. KaevCMS проверяет изображение перед выводом; поле в `module.json` не требуется.
